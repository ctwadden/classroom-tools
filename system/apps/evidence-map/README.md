# Evidence Map · Teaching Studio

A local teacher workspace for course planning, outcome evidence, skills, individual learning plans, readiness diagnostics and reviewed seating arrangements. This September 2026 update adds a reconciled teaching catalogue for Multimedia 12, Communications Technology 11 and IB Digital Society. Existing Computer Programming 12 features remain available.

## Open the application

Open `index.html` in a browser, or serve this folder at a consistent local address:

```sh
python3 -m http.server 8796 --bind 127.0.0.1
```

Then open http://127.0.0.1:8796. Keep the same browser and address for your working records: browser storage is specific to that origin. Opening a different port, browser or file URL does not transfer records. Use Resource Library → full JSON backup to move between them. No deployment was performed for this update.

Start in Course Studio. Import a roster under Courses, then use Skills & Evidence, Student OS and Readiness Diagnostic. Resource Library holds the new Excel workbook, all three original workbooks, the teacher guide, student tasks, starter art, student passport and fabrication briefs.

Open **Assignments & Rubrics** for the current dated assessment catalogue, linked lessons/outcomes, available task rubrics, preparation checks and assignment evidence. **Sprint Overview** connects those assignments to the newer architecture. The earlier assessment and sprint catalogues remain explicitly labelled and retain historical records. Starting an evidence record from an assignment preserves its assignment/catalogue/rubric references. See [the assignment integration repair report](help/Assignment_Integration_Repairs.md) for scope, verification and remaining fabrication work.

## What is included

- 332 dated lesson rows, with ten matching Citrus lesson replacements and four assessment revisions. Thirty date-neutral opening tickets and fourteen sneaker lessons remain as alternatives.
- 40 proposed skills: twelve per target course and four shared habits. Each has observable evidence, a next teaching action and local descriptors.
- A private learner passport with dated skill claims and evidence references. Teacher import preserves claims unverified; inspecting the work creates separate teacher evidence.
- A four-criterion Photoshop baseline/retest and a separate Digital Society reasoning baseline/retest.
- Historical diagnostic attempts, missing-evidence checks, teacher-reviewed readiness bands, review dates and a mixed-team draft with manual swaps. The student seating file excludes readiness and private notes.
- A 13-sheet Excel workbook with blank student registers, formulas, validation, planning and sources. Spreadsheet edits and browser records are separate; there is no live sync.

Readiness is a local task-specific support-planning judgment. It is not a validated Kagan instrument, intelligence rank, fixed learning style, course percentage or IB grade. Teacher review remains necessary.

## Data and compatibility

Application records now commit atomically under `em_app_store_v2`. Existing raw keys remain unchanged as migration fallback. The student passport keeps its own browser log. There are no accounts or automatic cross-device/Google Sheets synchronisation.

A full JSON restore validates before preview and replaces outcomes, rosters, Studio and configuration in one write. Missing fields in an older full backup restore to empty defaults. A Studio-only restore is blocked if it would break shared outcome evidence. Keep dated full backups outside the browser. A recovery banner preserves raw stored data and unsaved candidates when writes fail.

New roster imports require stable student IDs. Existing legacy-prefixed IDs are retained when a matching original ID is re-imported. A roster update retains evidence for matching real student IDs. New IDs begin empty; changing an ID is not a safe way to rename a learner. Records for departed IDs remain in backup history and are not automatically assigned to a new student.

The former automatic conversions from local levels/IB grades to percentages are disabled. PowerSchool files are review snapshots with blank score fields until a school-specific reporting policy and import template are configured.

Multimedia now has five active published Sound outcomes and stable code-based portable identifiers. Historical Sound entries remain under their original keys in Student OS for individual review. IB learning targets are visibly local interpretations with official guide references.

The unauthenticated Gemini proxy is disabled and returns 403 without sending requests to an upstream provider. Local drafting remains available.

## Checks and maintenance

Core logic tests require Node.js:

```sh
node --test tests/catalogue.test.js tests/studio-core.test.js tests/persistence.test.js
```

`tests/browser-workflow.mjs` uses Playwright with a temporary browser profile and synthetic students. Set `EVIDENCE_MAP_URL` to the local server address if needed. It tests all 56 course/route combinations, persistence, diagnostic completeness/retesting, student claims, seating privacy, backups, planning preservation and mobile layouts.

The `tools/` scripts document source extraction and artifact generation. `build_catalog.py` defaults to the versioned consolidated JSON. Private intake is an explicit optional argument. `reconcile_curriculum.py`, `build_passport.py`, `build_help.py` and `build_creative_library.py` rebuild the authored views. `build_public.py` creates an allowlisted `dist/`; Netlify publishes that directory. Do not copy private data into `help/` or `outputs/gold-standard-2026/`. `build_workbook.mjs` uses `@oai/artifact-tool`; it translates only actual cell references to avoid the library’s fill-down issue with quoted course codes. Workbook tests include more than one assessment row and remove test records before export.

Local Git history includes a pre-repair baseline and the repaired release. Inspect the diff before choosing a code rollback. The pre-repair release snapshot also remains in `/private/tmp/evidence-map-audit-repairs/before-repairs.zip` for this session. Do not delete browser storage to roll back code. The release ZIP is a source/material package, not a backup of student records.

## Workbook claims integration · 16 September 2026

The app keeps student data in browser localStorage. The only server function is a disabled Gemini proxy; there is no claims POST endpoint. **Skills & Evidence → Import student claims** accepts one student export or one combined class JSON (up to 2,000 claims / 2 MB). One confirmation imports all valid claims through the existing validator and atomic store. Student IDs must exactly match the selected roster. Claims remain unverified; self-ratings are not teacher grades.

See [the architecture report and exact workbook contract](help/Student_Claims_Integration.md) and [the synthetic combined-file example](help/Student_Claims_Example.json). This clarification and import UI update have not been deployed.
