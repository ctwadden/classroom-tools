# TRUCK STANDARD 2.0 — Technology Learning System

**Purpose:** A reusable production and assessment system for software-exploration modules. Change the software/topic; keep the production logic.

## Non-negotiable principle
A tutorial is not "Truck Standard" because it looks polished. It earns the status only after the workflow, assets, curriculum alignment, evidence model, instructional manuscript, and final files have all passed QA.

## The 11-stage production pipeline
1. **Idea / Design Brief** — define finished product, audience, purpose, difficulty and time.
2. **Curriculum + Skills Map** — identify outcomes, target competencies, prerequisites, new skills and evidence.
3. **Source / Technique Research** — verify tutorials, videos, ebooks, PDFs and documentation; map timestamp/page → layer/object → tool → action → setting → result.
4. **Asset Plan + Acquisition** — accept only assets that pass resolution, angle, lighting, focus, rights and compositing-fit checks.
5. **Technical Prototype** — perform the complete workflow with the actual assets. No guessed steps survive.
6. **Demonstration Capture** — create source assets, actual checkpoints, screenshots, diagrams and Before → Action → After visuals.
7. **Instructional Manuscript** — write only after the workflow works; use Select First → Do → Why → Check → Fix where useful.
8. **Evidence + Assessment Map** — map Observation, Conversation and Product evidence to competencies/outcomes and prepare feedback stems.
9. **Resource Assembly** — standalone HTML, PDF, starter assets, exemplar, supports, teacher notes and project manifest.
10. **Truck Standard QA** — audit curriculum, technical accuracy, assets, redundancy, checkpoints, assessment, accessibility and files.
11. **Release + Registry** — publish to GitHub, update registry/spreadsheet, version the resource and set Verified only after every gate passes.

## Ten rules that prevent drift
1. No invented workflow steps.
2. Label Source Instruction, Modernized Equivalent and Classroom Adaptation.
3. Skills live outside projects; do not reteach Basecamp repeatedly.
4. Map outcomes before production.
5. Assets must pass an acceptance gate.
6. Separate source assets, instructional diagrams and actual checkpoints.
7. Complex steps show Before → Action → After.
8. No redundancy.
9. Assessment is Product + Observation + Conversation.
10. A tutorial is not released until QA passes.

## Evidence model
- **Obs:** what the teacher witnesses.
- **Con:** what the student can explain/justify/troubleshoot.
- **Pro:** what the saved file/output proves.

Completion alone is not mastery. Evidence accumulates over time and teacher confirmation remains required.

## Reuse across domains
The pipeline stays the same for Photoshop, Blender, After Effects, Cinema 4D, Virtual Production and Game Design. Only the domain skill registry, course/outcome map, asset types and software-specific QA change.
